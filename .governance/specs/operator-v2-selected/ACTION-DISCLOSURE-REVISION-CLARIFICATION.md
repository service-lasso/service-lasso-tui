## Exact proposed public semantics without new keys

Action.availability describes mutation readiness after all selected capability/policy/business checks. It does not assert that every projected metadata member is undisclosed when available:false. ActionForm.availability describes whether the complete authorized classified action form can be read from a genuine stable source. An unavailable root returns actions:[] as already selected. A disclosed action row may have unavailable operational Availability, expectedRevision:null, preserved authentic payloadPolicy, positively classified inputFields or null under the selected schema rules, and positively authorized payloadReferences. The client must render the row's unavailable operation truthfully and must not execute it, issue preview, infer permission, or use its reference choice as a grant.

The actual issuer must independently authorize action/reference disclosure using the trusted original request principal and enforced read/profile/general/special/manifest policy before inspecting or publishing private existence/labels. A denied root uses the selected typed auth error; an authorized root never includes a privately undisclosed action row. It must not fabricate an unavailable placeholder actionId/description for an undisclosed row. A disclosed action whose reference disclosure is denied or whose source cannot be inspected has payloadReferences:[] only together with the genuine unavailable source/policy result already required by selected reference V2; it must not present a ready empty roster as positive absence. These predicates are private source-owner decisions, not guessed mappings from Availability.reasonCode. Public choice readiness remains acquisition/authorization plus full original validator vocabulary support, never standalone schema satisfaction. Disclosed-but-operationally-unready choices may retain ready reference choice availability, but no mutation expectedRevision is issued and no preview may consume them until the same action is freshly ready with its exact current grant.

The complete form, every Action.definitionRevision and ServiceDetail.summary.definitionRevision for the same successful held read are proposed to use the one same original service-definition snapshot identity. ActionMetadata rows in that detail also use this identity. No action-specific digest or stale row may substitute for it. This equality is a NEW explicit relation proposed here, not a claim that CODECS98 already wrote it. The real owner must acquire and retain the service definition source snapshot, its registration identity/generation, all-writer modelEpoch and publication revision, classify each original row and finish the complete bounded roster before publishing. The old hash component may contribute to the identity only after actual held-source stability is proven; equality of copied hashes alone is not sufficient. A separately read detail/form may legitimately have a different revision after a real intervening writer. The client must treat that as changed state, retain the original preview, and require a fresh deliberate preview rather than replace a revision or token silently.
