# Nested declared-action payload schema amendment

Status: PROPOSED; requires parent selection and coherent pre-code adoption before product expansion. Original selected normative files remain unchanged.

## Grounded source and completing boundary

ServiceActionPayloadSchema in src/contracts/service.ts currently declares only type, required, properties and additionalProperties. The real validatePayloadSchema in src/runtime/actions/runs.ts checks those fields recursively; it does not enforce enum, numeric/string/array bounds or typed array elements. Selected CODECS29 requires the complete bounded nested subset and explicitly forbids promising more than the real validator enforces. Flat OperatorField cannot represent that subset. This amendment defines the missing public tree, typed array-element extension, and diagnostic selector convention; it is not evidence of their implementation.

## Exact public shape

Action.inputFields becomes a single PayloadSchema tree rather than the ConfigForm Field array. SetupStep.inputFields remains its separately owned baseline empty array; no setup-input declaration is inferred from action schemas or command text. Action inputFields is null only when inline payload is not available; a ready inline action carries a nonnull object-root schema. Unsupported source schema makes inline payload unavailable while preserving genuine independently available reference capability, without inventing an empty schema.

PayloadSchema has exactly types, constraints, properties, required, items. types is a nonempty unique array from string, boolean, integer, number, object, array, null, in that exact registry order; it preserves every original supported source type alternative, including multiple nonnull alternatives. Root types is exactly [object], reflecting the actual resolved payload owner object root. A number alternative admits integer values as the real source validator does; integer and number alternatives can both be present without deleting either original declaration. Null is its own alternative, distinct from absence. The typed editor offers every declared alternative and remembers its selected variant; switching variant deliberately rebuilds that node through typed controls, never arbitrary JSON. No useful original nested union is reduced to unavailable or a single type.

properties is an ordered array of exactly {name,schema}, sorted by original UTF8 name bytes, when types includes object; otherwise []. Names are original nonempty control-free UTF8 strings at most128 bytes, excluding the globally reserved keys. required is a sorted unique subset of those names, when types includes object; otherwise []. constraints is exactly {enum,minimum,maximum,minLength,maxLength,minItems,maxItems,additionalProperties}. Each numeric bound is null when its corresponding type alternative is absent; additionalProperties is false when types includes object, otherwise null. True or omitted/unconstrained source additional properties cannot become a closed editable object by projection. items is a nonnull PayloadSchema when types includes array; otherwise null. This explicitly adds source items to the same recursive source validator. It is a homogeneous element schema, never tuples or arbitrary raw JSON input.

minLength/maxLength are nonnull precisely when types includes string, safe nonnegative integers measured in Unicode scalar values, min<=max. minimum/maximum are nonnull precisely when types includes integer or number; bounds are finite safe-magnitude numbers with minimum<=maximum; integer-only bounds must be safe integers. minItems/maxItems are nonnull precisely when types includes array, integers 0<=min<=max<=128. enum is null or a unique nonempty array of typed JSON values, each independently conforming to at least one original type alternative, the same complete schema tree and its applicable bounds. Nested object/array enum values use the identical recursively typed public value grammar and cumulative limits; the editor selects an actual authorized enum choice and shows its safe typed tree, never a free raw-JSON fallback. Structural enum equality is recursive type/value equality with object keys compared by original UTF8 spelling independently of property insertion order, arrays positionally, and numbers by the admitted JSON numeric value. Schema/value classification authorization applies before exposing any enum content; private source values are never generically declassified. Constraints apply to the actual value variant, not to other admitted variants. Boolean/null variants have no numeric/string/array rules. No absent key, extra keyword, coercion, pattern, refs, recursive references or evaluator extension is admitted. Source omitted bounds are projected only as actual common request/type ceilings, not as evidence that the original source imposed a tighter bound. Enumerations have at most32 values. Source enum support is explicitly added to the real validator before availability.

Maximum schema depth8, total property declarations64, array extent128, and all existing request65536/response262144/depth16/value8192/property-name128/public-string4096 limits remain cumulative. Nested arrays count actual submitted values, not just schema nodes. Enumeration and numeric equality preserve selected JSON number semantics without normalization. The projection retains original source/schema identity privately and is bound to the exact declared action, canonical root, actor/client, definitionRevision, generation, modelEpoch and family expectedRevision. A source replacement invalidates old editing/preview; the client never reconstructs schema from a payload value.

## Typed editing and diagnostic selectors

The editor recursively displays original schema property labels and typed controls, presence/unset independently from null, homogeneous array add/remove with actual bounds, and enum choices. It never uses an unrestricted raw-JSON fallback. PreviewRequest remains discriminated by external actionId=declared_action_run and exact {declaredActionId,payload?,payloadRef?}; no input.kind is added. Server executes the same actual recursive validator against the resolved inline/reference/mixed payload under the original family claim and held reference owners, and independently checks payload policy.

Diagnostic selectors for declared payload are JSON Pointer strings rooted at /input/payload. Original property names use RFC6901 escaping (~ becomes ~0; / becomes ~1); array indices use canonical decimal 0 or nonzero digits without leading zeros, bounded by the submitted admitted array. Root selector /input/payload is valid. A property selector can refer only to an actual schema property at the corresponding node; a missing required property is permitted by the original schema even when absent from the payload. An array index can refer only to an admitted current request member; no guessed index for missing elements. Max selector128 UTF8 bytes; a deeper valid schema path exceeding it reports the nearest approved ancestor, never truncates. These are logical payload selectors, not filesystem paths. No submitted scalar/content/private reference value participates in the selector.

The producer constructs the approved selector set from the current validated schema plus original admitted request structure; the client independently constructs the same set from its retained exact schema/request. FieldErrors admit only members of that set and closed error codes; private/unavailable schema uses only the closed request-owner selectors, never dynamic values. Setup currently has no public dynamic input schema and therefore no dynamic setup field selectors; adding that remains a separate explicit source contract. Config selectors retain their selected actual form association; query/wire-member selectors retain their separately admitted owner convention.

## Complete-source obligation

Selection requires matching Core source schema type, manifest validation, recursive actual action validator, classified public projection, server policy/claim/preview/execute owner and Go codec/editor/diagnostics. Legacy accepted source schemas and original stored values remain retained; unsupported projection is unavailable, not silently rewritten or treated as validation success. Useful nested object/array editing and genuine provider references must be completed; unavailable-only delivery is not completion. No execution, native/source GO or publication is granted by this amendment.
