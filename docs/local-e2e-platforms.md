# Ordinary platform terminal evidence

Issue44 / SPEC006 extends the source E2E runner without changing the Linux PTY adapter or any native/release gate. The dedicated workflow runs Linux and Windows ordinary compatibility checks and a separately named **macOS exploratory deferred** check. Its frozen Core revision supplies the shared privacy and source-build fixture; full operator/v2 and guarded OAuth permission denial remain blocked independently.

Windows requires Python3.12 AMD64, Go1.26.0, Node22.23.2 and pywinpty3.0.5 installed from `scripts/requirements-conpty.txt` with `--require-hashes --only-binary=:all: --no-deps`. CI creates an owned private virtual environment. The runner receives the actual Python executable with `--python` and actual npm-cli.js with `--npm-cli`; Core invokes npm through the selected Node binary, never a `.cmd` shim. Python bytecode writes are disabled so tests cannot dirty the source checkout.

Before raw output or token acquisition, the runner verifies the exact clean Core source revision and imports its shared private utility. Windows roots are created with a protected inheritable current-user+SYSTEM DACL and actual readback; chmod is not used as Windows privacy. Full SID/ACE proofs remain private. Summaries carry only the verified policy and proof hash. Child profiles/cache/temp paths stay under private roots. The parent prepares empty private terminal/result files through the same Core writer before launching the token-bearing ConPTY child; Python retains those actual file descriptors, and the parent verifies their privacy afterward.

The approved CPython3.12 AMD64 wheel has SHA256 `d62946adf14b15b54c0b8d785f93fe18b04da23f4ad59e2e8c4612646e9abd23`; its `winpty/ptyprocess.py` has SHA256 `52a9ab4b0e8de72d775a96587982530f9e70e009ab89d11faf703093eb1c8988`. The adapter verifies that installed source hash before running. The [pinned upstream implementation](https://github.com/andfoy/pywinpty/blob/v3.0.5/winpty/ptyprocess.py) creates its socket reader/server/thread at lines39–51, implements close at126–141 and wait/isalive at237–252. Direct socket byte reads avoid its potentially blocking UTF-8 continuation read. Actual source status and wait must agree; EOF alone cannot pass q. Both original sockets close and the reader thread must join. Missing cleanup fields produce a failed result; forced cleanup never passes.

After actual healthy UI readiness, the Windows lane checks distinct new help text, Escape dashboard restoration, narrow/navigation keys, actual Core health/services reconnect counts, resize and q. It records timings, consistent actual wait status, pinned helper identity and token-leak Booleans. VT/wrap normalization is limited to visible help/token checks; raw bytes stay private. Source tests with fake transports prove failure handling, not Windows or native qualification. Matching-host CI must supply the platform evidence.
