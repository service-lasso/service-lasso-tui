# Ordinary source TUI end-to-end checks

Run from a clean TUI checkout with Go1.26.0, Node22.23.2 and Python3 on Linux:

```sh
node scripts/run-local-e2e.mjs --core-dir /absolute/core-checkout --expected-core-revision FULL_40_HEX_SHA --suite compat
```

First install Core dependencies with `npm ci --ignore-scripts --no-audit --no-fund` in its isolated checkout. The selected Core checkout must have no pre-existing `dist` output; use a fresh owned checkout for each source-build run. The exact Core checkout must provide `scripts/operator-e2e-fixture.mjs`. The helper builds that revision, creates private isolated workspace/registry/auth state, starts a real loopback API on port0, and announces private connection and public provenance receipt paths. Override its path with `--core-fixture-helper`; specify an absolute Go binary with `--go`. The client runner owns the helper and sends `stop\n` in `finally`, waits for its actual exit, and checks that its credential file disappeared. The existing user runtime is never selected automatically. Output defaults to a new private temporary directory; `--output-dir` must name a fresh path.

The runner verifies the selected clean Core revision before importing its shared private-directory utility. It creates and verifies a private evidence root before any raw log or credential handling (owner+SYSTEM protected DACL on Windows; mode0700 on POSIX). The runner builds the current clean TUI revision, checks embedded VCS metadata, verifies valid-token identity and that an invalid token does not become a local-token actor, and drives its real POSIX terminal. Keyboard input waits for rendered UI and noncanonical terminal mode, including the initial terminal-color query delay. Compatibility coverage includes healthy dashboard, distinct help, Escape return, narrow/navigation/reconnect, resize and normal q with actual child wait. Raw terminal/build streams remain private; public `summary.json` contains closed stage results, source/artifact hashes, monotonic timings and token-leak Booleans. Retain evidence until review, then remove only your own output directory.

`--suite all` is the default. Compatibility success does not pass the v2 operator suite: the v2 stage observes unavailable/error UI and quit resilience but remains BLOCKED until full useful v2 journeys can run against the authoritative Core API. Both `all` and `v2` return nonzero for that missing qualification. This is separate from native profile/custody, installed-byte integration, publication and release acceptance.

Windows selects the ordinary ConPTY adapter with explicit Python3.12 AMD64 and hash-pinned pywinpty3.0.5. Supply `--python` for that environment and `--npm-cli` for the actual npm-cli.js file. The automatic platform workflow prepares both with the shared Core privacy bootstrap. macOS uses the unchanged POSIX adapter as separately named exploratory/deferred evidence, without borrowing Windows/Linux GA or native acceptance. See [platform setup and evidence](local-e2e-platforms.md). Source fixture tests run with `node --test scripts/local-e2e.test.mjs`; their synthetic terminal proves observer timing/EOF behavior, never real backend or native authority.

Authentication-negative identity is distinct from access denial: local loopback fallback can remain local-root. Permission/lifecycle denial is visibly BLOCKED pending a genuinely guarded OAuth fixture. Reconnect is bound to increased actual successful health/services request counts in the Core owner’s request observations, rather than a possibly coalesced redraw.
